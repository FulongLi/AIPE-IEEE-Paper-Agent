# IEEE Paper Agent

Read `README.md` for the repository map and `core/SKILL.md` for task routing.
All instruction paths are relative to the repository root. The maintained policy
and workflow layer is `core/`; release copies are generated by
`scripts/package-release.py`. Do not edit generated packages.

For a research idea, follow `core/workflows/idea-to-paper.md`. For a paper plan,
follow `core/workflows/paper-production.md` and its manuscript-generation workflow.
Read the relevant policies under `core/policies/` before drafting or auditing.

Choose `venues/<id>/profile.json`, then initialize the actual venue template with
`scripts/create-manuscript.py --venue <id>`. Preserve official template files and
use manuscript-local relative paths. Keep the research spine, evidence mapping,
and missing-evidence priorities defined by the core workflows.

Domain packs are optional. Only for power electronics, load
`domains/power-electronics/README.md`; it routes to curated knowledge, terminology,
and the existing `PE_IEEE_reference/` collection. Generic IEEE work requires no
domain pack or repository reference collection.

The `books/` directory and private extraction caches are local-only resources;
follow the domain source manifest. Do not commit full converted textbooks.

For repository changes, run `python -m unittest discover -s tests -v`, check
manuscripts for all supported venues, rebuild the reference index, and generate
release packages. Tests must protect template integrity, venue differences,
portable paths, and generated instruction provenance.
